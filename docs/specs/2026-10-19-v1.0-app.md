# v1.0: the app

Goal: an Android app replaces the Telegram bot as the way to use feed-eater. One daily stack of cards you swipe through, a library of what you
saved (feed-eater's own, with AI on it, instead of Karakeep), and every Telegram feature on a real screen. One quiet notification a day instead of
a message per item. Tailnet only.

Decided with the owner 2026-10-19:
- Android, Kotlin, native. Same stack as the owner's other Android apps (Compose, Material 3, Hilt, Navigation, kotlinx.serialization,
  coroutines, WorkManager, Room, minSdk 31), in `android/` of this repository so the API and the client change in one PR.
- Telegram goes: full parity in v1.0, and the owner's deployment drops `Telegram:Token` on release day.
- Swipe up saves into feed-eater's own library, with AI on it, not into Karakeep.
- Reachable on the tailnet only. No public exposure, no login service.

Facts this rests on (read from `main` at 98eb1ee…f1ed88c, 2026-10-19):
- No JSON API exists. Routes are `/ui/*` (server-rendered, cookie login), `/mcp` (`Mcp:Token`) and `/healthz` (`Program.cs:63`,
  `Ui/UiEndpoints.cs:58-88`). The v0.9 spec planned `/api/v1` and scoped tokens; none of it is built (`grep api/v1 src` finds only the HN client).
- Every interactive action is a Telegram callback (`Telegram/CallbackData.cs`): vote up/down, idea, save, duel a/b/skip, follow, unfollow.
  Commands (`Telegram/CommandHandler.cs`): `/ask /digest /feeds /follows /learn /quiet /search /unfollow`. Free-text replies to an item are
  turned into one of those actions, a feed mute, or an answer about the item (`Telegram/ReplyHandler.cs`).
- Jobs that push to Telegram: `Digest/DigestJob`, `Digest/DigestRun`, `Duels/DuelJob`, `Follow/StoryFollower`, `Hype/AutopsyJob`,
  `Review/WeeklyReview`, `Watch/ReleaseWatcher`, plus the Monday ideas shortlist (#19, `Plane/IdeaSinks.cs`).
- `saved(item_id, karakeep_id not null, at)` (migration 0007) records 📌 saves; saving calls Karakeep (`Signals/KarakeepClient.cs`). Usage
  2026-10-18: 5 saves, 37 Karakeep bookmarks in total, 14 of them links.
- Push on the owner's phone already goes through a self-hosted ntfy server on the tailnet (the owner's home widget reads it with Basic auth).
- LLM spend is about $0.08 a day in total (14 days to 2026-10-18: $1.13), so AI on saved items costs little.

## What the app is
An inbox with one rule: it ends. Each day feed-eater produces a stack of cards; you swipe until "done for today". Everything that used to be
a Telegram message is a card. Everything that used to be a command is a screen. Saved things land in the library, which feed-eater reads,
summarises and searches like the rest of the archive.

## Server

### 1. Cards (the inbox)
New table `cards(id, kind, item_id null, ref_id null, payload jsonb, created_at, due_at, expires_at null, shown_at null, acted_at null,
action null)`. Jobs stop calling Telegram; they add cards through one `IInbox` service. Kinds:

| kind | made by | payload | swipe right | swipe left | swipe up | tap |
|---|---|---|---|---|---|---|
| `item` | digest | title, feed, summary, why, suggestion, link | 👍 | 👎 | save | open |
| `train` | "train more" (below) | as `item` | 👍 | 👎 | save | open |
| `duel` | DuelJob | two items | — | — | skip | pick A or B |
| `follow` | StoryFollower | story, new item | keep following | stop following | save | open |
| `release` | ReleaseWatcher | package, from→to, verdict | seen | mute this package | — | open notes |
| `idea` | Monday shortlist | idea, source item, target project | keep | drop | — | open |
| `review` | WeeklyReview | the week's summary | seen | — | — | open |
| `autopsy` | AutopsyJob | report | seen | — | — | open `/ui/autopsy` |
| `resurface` | library (below) | saved item unread 14+ days | keep | remove from library | — | open |
| `notice` | system | "no digest today: …", feeds failing 3 times | seen | — | — | open |

Order: `notice`, then due cards by kind priority (`item`, `follow`, `duel`, `idea`, `release`, `review`, `autopsy`, `resurface`), then
score. Cards past `expires_at` drop out unseen (digest items after 3 days, follow updates after 7). After the last card the app offers
**Train more**: up to 20 items that passed triage but were not shown, as `train` cards. The learned ranking needs 100 votes with 10 of each
and votes have stalled at 1 to 2 a day, so this is the cheapest way to make the ranking learn.

`idea` keep/drop: #19 already files the shortlist in Plane Intake. Before building, read `Plane/IdeaSinks.cs` and decide one of two:
(a) the shortlist waits for the swipe and only *keep* files it, or (b) it is filed as now and *drop* closes the Intake item. Prefer (a): it
stops unreviewed items reaching Plane.

During the move the Telegram code renders cards too (one adapter), so the bot keeps working until its token is removed, and a stranger's
instance without the app behaves as today.

### 2. API (`/api/v1`, JSON)
Minimal API over the same services Telegram calls now; no logic moves into handlers.

- `GET /stack?after=` → ordered cards, plus `{remaining, doneForToday}`.
- `POST /cards/{id}/act` `{action, clientId}` → idempotent on `clientId` (a UUID made on the phone), so a retried swipe never counts twice.
  `POST /cards/{id}/undo` `{clientId}` reverses the last action on that card within 24 h (vote removed, save removed, follow restored).
- `GET /items/{id}` → full text (stored content, else fetched through `SafeFetcher`), summary, why, suggestion, feed, vote, saved state.
- `POST /items/{id}/ask` `{question}` → answer from that item's text. `POST /ask` `{question}` → the existing `/ask` with checked citations.
- `GET /search?q=&kind=&project=&from=&to=` → the existing search.
- `POST /library` `{url, title?, text?}` → save anything (share sheet, below). `GET /library?state=unread|read|all`;
  `POST /library/{itemId}/read`; `DELETE /library/{itemId}`.
- `GET /follows`, `DELETE /follows/{id}`; `GET /feeds` (with the 👍 rate and failures), `POST /feeds` `{url}`, `POST /feeds/{id}/mute`,
  `DELETE /feeds/{id}`.
- `GET /settings`, `PUT /settings` → quiet hours, `/learn` switch, which kinds may notify, digest time.
- `POST /digest/run` → run now (as `/digest`).

Authentication: table `api_tokens(id, name, hash, scopes, created_at, last_used_at)`. Only a SHA-256 hash is stored; the token is shown
once. Scope `app` covers all of the above. `/ui/setup` gets **Pair a phone**: a QR code holding `{baseUrl, token}`, and a revoke button per
token. `Mcp:Token` keeps working for `/mcp` and `/ui` only. Rate limit per token, 64 KB bodies, no CORS. Errors are RFC 7807 problem
details. OpenAPI document at `/api/v1/openapi.json`.

### 3. Library (own save, with AI)
`saved` changes: `karakeep_id` becomes nullable; new columns `source` (`swipe`, `share`, `import`), `read_at`, `note`.

When something is saved:
1. It becomes an item if it is not one (`POST /library` with a new URL creates an item with no feed, `source_key = share:<canonical url>`,
   deduplicated by canonical URL like any other item).
2. Full text is fetched once through `SafeFetcher` and stored (`extra_text`), so the item is readable offline and searchable.
3. With no summary yet, the read model writes one plus `why` against the profile, and the item is embedded. Cost: one read call per save.
4. It counts as a like (same weight as 📌 today), so saving teaches the ranking.
5. `Karakeep:Mirror` (default false) still copies it to Karakeep for anyone who wants both. Bookmark import from Karakeep stays as an
   optional one-time import (`import` source).

Weekly, saved items unread for 14 days come back as `resurface` cards, at most 3 a week, so the library doesn't turn into a second pile.
The library is in the MCP tools too (`feed_search` gets `saved=true`), so agents can use it.

Text notes are not supported, on purpose: the library holds links and articles. Credentials belong in a password manager.

### 4. Push
`Push:NtfyUrl`, `Push:Topic`, `Push:Token` (optional). One message a day when the stack is ready: "9 cards", click URL
`feedeater://stack`. A kind may also notify on its own only if Settings allows it (default: none). Quiet hours hold every message.
Nothing else ever pushes. No push settings → no push, the app just shows the stack when opened.

### 5. Doctor
`doctor` checks the push target (`ok`, `off`, `FAIL` with the fix) and lists API tokens with their last use. With `Telegram:Token`
empty it reports Telegram `off`, not a failure.

## App (`android/`)

Package `io.github.feed_eater`, single `app` module (split later only if a second module earns it). Layers: `api` (Ktor or OkHttp +
kotlinx.serialization, models matching the OpenAPI document), `data` (Room: cached stack, items, library, outbox), `ui` (Compose screens,
ViewModels), `work` (WorkManager sync).

Screens:
- **Pairing.** Scan the QR from `/ui/setup`; token kept in EncryptedSharedPreferences. HTTPS only (no cleartext exception, since the app
  must not name a host); the deployment serves feed-eater on an HTTPS name reachable only on its private network.
- **Stack.** One card at a time, the next card peeking behind. Swipe thresholds at 35% of the width (up: 25% of the height), with haptics.
  The swipe direction shows its label while dragging (👍, 👎, Save). An Undo button after every action. The same actions as buttons under
  the card and as TalkBack custom actions, so nothing needs a gesture. Empty state: "Done for today", **Train more**, **Run digest now**.
- **Reader.** Full text, summary, why, suggestion; actions in a bar; **Ask about this** (question box, answer under it); **Follow**;
  **Mute feed**; **Note** (free text kept on the save).
- **Library.** Unread / Read tabs, search inside, swipe to mark read or remove.
- **Search & Ask.** One box: a question goes to `/ask` and shows the answer with its citations; plain words go to search.
- **Follows.** Active stories, stop following.
- **Feeds.** List with 👍 rate and failures, add by URL, mute, remove.
- **Settings.** Quiet hours, learn switch, digest time, which kinds may notify, paired server, sign out.

Share sheet: the app accepts `text/plain` links from any app. A small sheet offers **Save to library** or **Add as feed**.

Offline and a flapping tailnet: the stack, opened items and the library are cached in Room. Actions go into an outbox and are sent in
order by WorkManager when the server answers, with exponential backoff. The UI applies them at once. Anything older than 15 minutes
without a sync is shown with a grey "offline, last synced …" bar.

Deep link `feedeater://stack` opens the stack from the ntfy notification.

Release: CI builds a signed release APK on tag `app-v*` and attaches it to the GitHub release; install with adb or Obtainium.

## Errors
- Server down or tailnet gone: the cached stack keeps working and actions queue; the grey bar shows it.
- Token revoked: 401 → back to Pairing, the outbox is kept and sent after pairing again.
- An action on a card that expired or was already acted on: the server answers 409 with the current state; the app takes it without an error.
- Push target down: the digest still runs; doctor and `/ui` show the failure; nothing retries more than once an hour.
- Fetch of a saved page fails (403, paywall): the item is saved with the feed or shared text, marked "no full text".

## Testing
- Server (existing suite): per endpoint scope checks, 401/409/problem details; idempotent `act` (same `clientId` twice = one vote); undo
  for every action; every job produces its card kind; the parity table row by row; the library pipeline (new URL, duplicate URL,
  fetch failure, mirror on/off); push off, push failing, quiet hours; a stranger instance without app settings behaves as v0.8.6.
- `OwnerTermsTests` scans `android/` as well: the app ships with no owner host, address or name; the server address comes from pairing.
- Contract: JSON fixtures for every response type live in `tests/contract/`; the server tests produce them and the Android tests parse them,
  so a breaking change fails on both sides.
- App: unit tests for the outbox (ordering, retry, 409), the stack ViewModel, and the share sheet; Compose UI tests for swipe thresholds,
  undo, and TalkBack actions; screenshot tests of each screen in light and dark (as in the owner's home widget).
- Before release: a second agent's risk review, as for v0.7 and v0.8.

# v0.7: anyone can run it

Goal: a stranger runs their own single-user instance with `docker compose up`, an OpenAI-compatible key, a Telegram bot and an OPML
file. Nothing in the code knows the owner or the owner's homelab; the owner's setup becomes configuration in `homelab-gitops`.

Evidence for every claim below is the 2026-10-06 coupling audit (file:line references are to commit 73edb31, `src/FeedEater/`).

## Principles

1. **Empty means off.** Every optional integration (Plane, Karakeep, GitHub, Hindsight, release watch, page fetch) is off until its
   setting is filled. An off integration registers no background work, shows no button, and costs nothing. Today only Karakeep is
   like this (`SignalJob.cs:27`).
2. **Required core, nothing else:** Postgres with pgvector, an OpenAI-compatible endpoint (chat and embeddings), a Telegram bot.
   Feeds come from the built-in reader or, optionally, Miniflux.
3. **No owner in code.** No name, pronoun, city, address, account or project in `src/`, `config/`, defaults, prompts, tool
   descriptions or docs shipped in the image. Personal values live in the deployment's config.
4. **Same behaviour for the owner.** The owner's deployment must run the same effective config before and after. The v0.7 PR is
   paired with a `homelab-gitops` PR that sets every value whose default changed; the effective config (v0.6 defaults plus compose env, against v0.7's `--print-config` with the new compose env) must match.
5. **Fail loudly at setup, quietly at runtime.** `doctor` and the setup page say what is wrong and how to fix it; a missing optional
   service never makes the digest fail or loop forever.

### D2. Integration switches
Add `bool Enabled` (computed: the required setting is non-empty) to `PlaneOptions`, `KarakeepOptions`, `GitHubOptions`,
`HindsightOptions`, `WatchOptions`, `MinifluxOptions`, `FetchOptions` (off when `MaxPerDay` is 0). Registration reads only these
properties. Buttons: 📌 hidden without Karakeep (`DigestFormatter.cs:126`); 💡 stays (see D3).
Failures of an enabled optional service are logged per source and retried on the normal schedule; they never throw out of a job
that has other work (the `SignalJob` per-source catch is the model; fix its retry-forever case at `SignalJob.cs:49`).

### D3. Ideas go through a sink
`IdeaFiler` gets an `IIdeaSink`. Sinks: `plane` (today's behaviour), `local` (the always-on default: the idea is stored in the
existing `ideas` table and shown on `/ui/ideas` and by the MCP tool `feed_ideas`). With Plane off, 💡 works and says "Saved as an
idea". Later versions add `github-issues` and `webhook` sinks without touching callers. `FileAsync(itemId, project, text)` keeps its
signature (v0.6).

### D4. Built-in feed reader (the biggest piece)
`Source:Kind` = `builtin` (default) | `miniflux`. Switching kinds on a populated database is unsupported and documented.

- **Schema (migration 0010):** `feeds` gains `etag`, `last_modified`, `last_fetched_at`, `next_fetch_at`, `fail_count`,
  `last_error`; `items` gains `source_key text` (unique) = `feed_id:sha256(guid or url)`; existing Miniflux rows get
  `'mf:' || miniflux_entry_id`. `miniflux_entry_id` stays, nullable (already nullable, 0001:12). New feeds take ids from a sequence
  starting above 10^9 so they never collide with Miniflux ids.
- **Fetch:** RSS 2.0, Atom, JSON Feed, via the existing `SafeFetcher`. Conditional GET (ETag/Last-Modified), at most one request per
  host per second, a per-feed interval (default 30 min, backoff to 24 h on repeated failure, `fail_count` reset on success),
  response cap 5 MB. Private hosts are refused unless listed in `Source:AllowedHosts` (self-hosted RSSHub, Nitter, etc.).
- **Items:** HTML content as given, `published_at` from the entry (fall back to first-seen time, never null, 0001:18), canonical URL
  normalised like today, dedupe by `source_key` then by the existing title-hash rule.
- **Full text for short items** (replaces `DigestRun.FullTextAsync` through Miniflux, `DigestRun.cs:278-301`): `SafeFetcher` +
  `ReadableText`, same size caps as page fetch.
- **Management:** `/ui/sources` gets add (URL, with discovery through `FeedDiscoverer`), remove, import OPML (upload) and export
  OPML; Telegram `/feeds` (list), `/feeds add <url>`; CLI `FeedEater.dll import-opml <file>`. Categories come from OPML folders.
- **Health:** loop name `feeds`; the "source unreachable" note in the digest header (`DigestRun.cs:93`) names the failing feeds, not
  Miniflux. Per-feed error shows on `/ui/sources`.
- **First start:** a new instance embeds only items from the last `Source:BackfillDays` (default 14), not the whole history
  (`Ingestor.cs:61`), so the first run costs cents. Miniflux mode keeps today's behaviour.
- **Miniflux mode** stays as it is, behind `MinifluxOptions.Enabled`, including `FullTextAsync` through Miniflux.

### D5. Setup that works the first time
- `compose.example.yaml` (feed-eater + `pgvector/pgvector:pg18`) and `.env.example` with every required key and a comment per key.
  Image published for `linux/amd64` and `linux/arm64`; Dockerfile gets `HEALTHCHECK` on `/healthz`.
- **Profile:** if `ProfilePath` is missing, the embedded neutral example profile is used and the digest header and `/ui` say
  "Using the example interests; edit /config/profile.json". The example ships inside the image. The digest no longer fails on a
  missing file (today it fails every run).
- **Telegram bootstrap:** while `AllowedUserId` is 0, the bot answers `/start` with the sender's numeric id and the exact setting to
  set, and answers nothing else; sends are refused with a log line (today they go to chat 0 after spending on the LLM,
  `DigestRun.cs:44`). `AllowedUserId` 0 is a `doctor` failure.
- **`FeedEater.dll doctor [--print-config]`:** one line per integration: `ok`, `off` (not configured), or `FAIL` with the reason and
  the fix. Checks: database and `vector` extension; LLM chat and an embedding call that must return 1536 dimensions
  (`vector(1536)` is fixed, 0001:21; models that accept `dimensions: 1536` work); Telegram `getMe`; each enabled optional service;
  the feed source (at least one feed, one fetch succeeds); profile file (valid, or example in use). `--print-config` prints the
  effective config with secrets masked, one `key=value` per line, sorted (used for the before/after diff in principle 4).
  Exit code 1 if a required item fails. Works with env vars only.
- **`/ui/setup`:** the same table, read-only, behind the existing UI login.
- **LiteLLM cost header** (`LiteLlmClient.cs:104`): without it cost is unknown, not 0. Optional `Llm:Prices` (per model, USD per
  million tokens in/out) estimates it; otherwise spend pages show tokens and "cost unknown", and `eval --max-usd` refuses to run
  without prices instead of silently never stopping (`EvalRunner.cs:68`).
- `docs/SETUP.md`: 10-minute quick start (compose, key, bot, OPML, `doctor`), then one short section per optional integration, then
  upgrade notes. README leads with it; the owner's deployment notes leave the README.

## Built differently from this spec (branch A, 2026-10-06)
- `Llm:BaseUrl` default is `https://api.openai.com/v1/` and client paths are relative (`embeddings`, `chat/completions`); the owner sets
  `http://100.64.0.2:4000/v1/`.
- `Ideas:Sink` defaults to `auto` (Plane if configured, else local), so the owner's behaviour is unchanged.
- Migration 0010 is branch B's (feed fetch state, `source_key`); branch A's is 0011 (`llm_usage.cost` nullable).
- `Watch:FallbackPath` empty now means "no list, watch off". The owner's 63-row `config/watch.json` moved to
  `config/watch.example.json` behind an allowlist entry; replace it with a neutral 5-row example and mount the owner's list from
  `homelab-gitops` before v0.7 ships (follow-up, principle 3).
- `Ingestor` stays registered in both modes (branch B owns it); A skips only its Miniflux pass when Miniflux is off.

## Acceptance
1. **Stranger test (fresh directory, no homelab access):** `compose.example.yaml` + an OpenAI key + a Telegram bot token + an OPML
   file with 10 feeds → `doctor` has no FAIL; `/start` shows the user id; after setting it and restarting, `/digest` sends a digest
   within 15 minutes of first start. Miniflux, Plane, Karakeep, GitHub and Hindsight are never configured. Cost of that first
   run is printed on `/ui/usage`.
2. **Owner test:** the paired `homelab-gitops` PR keeps `doctor --print-config` identical before and after (diff attached to the PR),
   and the next scheduled digest arrives as usual.
3. `grep -rniE 'yehor|egoushka|hrabovsk|100\.64\.|hedzer|kyiv|jarvis|homelab' src config profile.example.json Dockerfile` matches
   nothing except an explicit allowlist file checked by a test.
4. Full test suite green; new tests for: each integration off, builtin fetch (conditional GET, redirect, 404, huge body, private
   host refused/allowed, malformed XML), OPML import/export round trip, `source_key` dedupe across both source kinds, doctor output,
   `/start` bootstrap, missing profile, `Llm:Prices`.

callback marks the source item 👍×3 when the issue is done, 👎 when cancelled; Plane first, GitHub Issues second); Backlog

**v0.9, plugs into the owner's setup, through generic hooks:** outbound signed webhook per action; inbound API (`POST /api/v1/questions`,
`/api/v1/items`) with scoped tokens; `Delivery:InterruptUrl` (senses can_interrupt) and `Delivery:AlertUrl`; Renovate sidekick (needs a
GitHub token and the PR comment API); voice notes through any `/audio/transcriptions` endpoint; "Try it on the box" as a webhook to the
owner's automation (chargehand has no live change mode, see integrations audit); "Ears on" as an inbound questions API that nytka
fills; session briefing as an MCP resource; post fuel; alert pack. The hooks stay generic: nothing in the repo names senses, nytka,
chargehand or JARVIS.

**Integration facts to design against (audit 2026-10-06):** senses answers only over MCP (`senses_can_interrupt`, Bearer token,
tailnet 8102), nytka has REST + HMAC webhooks, chargehand can research over HTTP but cannot draft a PR from outside yet, LiteLLM has

notes, the air-raid token (`ALERTS_IN_UA_TOKEN`) is not configured on the box.

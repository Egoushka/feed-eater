# v1.0 step 4: Library — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** saving puts an item in feed-eater's own library — from a swipe, Telegram, `/ui`, the API, or any URL shared from the phone — where
it gets its full text, a read (summary, why) and an embedding, counts as a like, and comes back as a card if left unread; Karakeep becomes an
optional mirror plus a one-time import.

**Architecture:** one `LibraryService` owns saving and unsaving; every caller that talks to Karakeep today calls it instead. Saving is fast
and local (vote + `saved` row, a feed-less item for a new URL). A `LibraryEnricher` loop then fetches full text, reads and embeds saved items
that lack them, so a model or network failure never loses a save. The read step moves out of `DigestRun` into `ItemReader`, used by both.
A weekly `ResurfaceJob` adds `resurface` inbox entries; `/api/v1/library*` and a `saved` search filter expose the library.

**Tech stack:** .NET 10, Dapper/Npgsql, xUnit + Testcontainers + `WebApplicationFactory`; no new packages.

**Spec:** `docs/specs/2026-10-19-v1.0-app.md` (Server 5). Master plan: `docs/plans/2026-10-19-v1.0-app.md` (step 4).

## Global constraints
- A save never fails because Karakeep, the model, the fetcher or the embedder is down; it is stored and enriched later.
- Saving is idempotent per item: a second save of the same item or URL returns "already saved" and writes nothing new.
- A new URL becomes an item with no feed, `source_key = 'share:' + canonical URL`; an existing item with that canonical URL is reused (never a new duplicate row).
- The library holds links and articles only; no free-text notes as items (a `note` on a saved item is allowed).
- With Telegram on, the 📌 button keeps its text; it now shows whenever the library exists (always), not only with Karakeep.
- Swipe guards stay: the swipe path calls no LLM (enrichment runs in the loop, never in a request).
- Migration `0032_library.sql`; new tables in `PostgresFixture.ResetAsync`; `0032` in `CombinationTests`' lists.
- Endpoint test classes share one host per class; contract fixtures for every new response (`UPDATE_CONTRACT=1`).
- `dotnet test FeedEater.slnx` (Docker; outside the sandbox) and `dotnet format --verify-no-changes` before each commit.

## Decisions taken in this plan (rulings, recorded)
- **R-m. Enrichment is asynchronous.** `LibraryEnricher` (a polling loop, every 30 s while there is work, else every 5 min) handles saved items missing full text, a read or an embedding, a few per pass, oldest first, each step retried on the next pass (max 5 attempts per item, then left as is and shown "not enriched"). The spec's "readable offline within a minute" holds when the services answer.
- **R-n. The library read passes no GitHub facts or linked-page text** (the digest computes those per run); same prompt, same model, same `reads` row.
- **R-o. Sources:** `saved.source` ∈ `swipe | telegram | ui | api | share | import`. Imports from Karakeep write **no vote** (bookmarks already count as likes through `signals`); every other save writes vote +1 at weight 1, as swipe saves do today.
- **R-p. Undo of a save** deletes the `saved` row only if the act created it: `swipe_acts` gains `previously_saved boolean`, captured at act time. The Karakeep mirror bookmark, if any, stays.
- **R-q. Resurface:** weekly (Sunday 10:00 local), saved items unread for 14+ days, at most 3 entries a week, an item resurfaced at most once every 30 days; acts `keep` (done), `remove` (unsave), `read` (mark read), `open`.
- **R-r. Karakeep:** `Karakeep:Mirror` (default false) copies new saves to Karakeep after the local save; `import-karakeep` is a CLI command that pages through link bookmarks once and saves each URL with source `import`.

## Review focus
1. **Saving the same URL twice, or a URL that already exists as a feed item:** one item, one `saved` row, no new duplicate. Task 2.
2. **Model/fetcher/embedder down at save time:** the save succeeds; enrichment retries later; after 5 failures the item stays saved and searchable by title. Task 3.
3. **Undo of a save the act did not create** (item saved earlier on Telegram): the library row stays. Task 4.
4. **Hostile shared URL** (`javascript:`, `file:`, private address): refused with a 400 problem; the fetcher's existing guards apply to anything fetched. Task 5.
5. **Telegram unchanged** for the owner except that 📌 shows without Karakeep and no longer says "Karakeep is not reachable". Task 4.

### Task 2: LibraryService — save, save a URL, unsave

**Interfaces produced:**

```csharp
public enum SaveStatus { Saved, AlreadySaved, NoItem, BadUrl }
public sealed record SaveResult(SaveStatus Status, long? ItemId);

public sealed class LibraryService(LibraryStore library, ItemStore items, FeedbackStore feedback, KarakeepClient karakeep,
    IOptions<FeedEaterOptions> options, TimeProvider time, ILogger<LibraryService> logger)
{
    public Task<SaveResult> SaveAsync(long itemId, string source, CancellationToken ct);           // vote +1 w=1 unless source == "import"
    public Task<SaveResult> SaveUrlAsync(string url, string? title, string? text, string source, CancellationToken ct);
    public Task<bool> UnsaveAsync(long itemId, CancellationToken ct);                              // the vote stays (undo restores votes separately)
}
```

Behaviour:
- `SaveUrlAsync`: accept only absolute `http`/`https` URLs up to 2,048 chars (else `BadUrl`); canonicalise (`UrlCanonicalizer`); reuse `FindByCanonicalAsync`; else insert `NewItem(EntryId: null, FeedId: null, Url: url, CanonicalUrl, TitleHash.Of(title), Title: title ?? host, PublishedAt: now, Content: HtmlText.ToPlain(text ?? ""), SourceKey: "share:" + canonical)`; an `InsertAsync` null (key exists) → look the item up by `source_key`. Then `SaveAsync`.
- `SaveAsync`: missing item → `NoItem`; `library.AddAsync` false → `AlreadySaved` (no vote write); else vote (R-o), then the Karakeep mirror when `Karakeep.Mirror && Karakeep.Enabled` and the URL is http(s): `CreateLinkAsync`, store the id; any mirror failure is logged and ignored.
- No LLM, fetch or embed call here (R-m).

- [ ] **Step 1: failing tests** (`LibraryTests`): save an item → one `saved` row with the source and a vote (+1, weight 1); save again → `AlreadySaved`, vote `at` unchanged; import source → no vote; `SaveUrlAsync` with a new URL → a feed-less item with `source_key` `share:…`, then again with the same URL plus `utm_source` → same item, `AlreadySaved`; a URL equal (canonically) to an existing feed item → that item is saved, no new row; `javascript:alert(1)`, `file:///etc/passwd`, a relative URL → `BadUrl`; mirror on with Karakeep answering 500 → still `Saved`, `karakeep_id` null; mirror on and OK → `karakeep_id` stored; `UnsaveAsync` removes the row and keeps the vote.

### Task 3: enrichment — ItemReader and LibraryEnricher

**Interfaces produced:**
- `ItemReader(AnalysisStore analysis, ProfileStore profiles, LiteLlmClient llm, IOptions<FeedEaterOptions> options)`: `ContextAsync(ct) → ReadContext` (about, profile list, keys — what `DigestRun` builds once per run, `DigestRun.cs:130-155`) and `ReadAsync(Candidate c, string text, ReadContext ctx, string? facts, string? linked, ct) → ReadResult?` (the prompt, model, 600 tokens, `LlmJson.Read`, `SaveReadAsync` — moved verbatim from `DigestRun.cs:217-250`). `DigestRun` calls it; its behaviour and tests stay unchanged.
- `LibraryEnricher : PollingLoop` (or the repo's loop base): each pass takes `PendingEnrichmentAsync(Library.EnrichBatch)` and per item: full text via `ItemText.FullTextAsync(itemId)`; a read via `ItemReader` when the item has none (no facts, no linked text — R-n); an embedding when `embedding is null` (`Ingestor.EmbedText` + `LiteLlmClient.EmbedAsync` + `ItemStore.SetEmbeddingsAsync`); then `RecordAttemptAsync(itemId, done: all three present)`. Any exception from one step is logged, counted as an attempt, and the next item goes on. Interval: 30 s after a pass that found work, else `Library.EnrichIdle` (5 min). Registered when `RunJobs`.
- Options `Library` section: `EnrichBatch` (5), `EnrichIdle` (00:05:00), `ResurfaceDays` (14), `ResurfacePerWeek` (3) with `[Description]`s.

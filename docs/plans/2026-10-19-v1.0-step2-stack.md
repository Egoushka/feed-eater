# v1.0 step 2: One stack — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a swipe session starts with the day's notices, digest items and inbox entries, in that order and unshuffled, ahead of recall, seeds
and ranked items; every new card kind has its view and acts; acts carry a client id, so a repeat runs once, and an act can be undone; the digest
runs without Telegram.

**Architecture:** `SwipeService.BuildQueueAsync` gets an unshuffled head built from `InboxStore` and the latest digest. Queue slots keep the
existing `(kind, id)` arrays; for inbox kinds the id is the inbox row id, for `digest` the item id. `CardView` gains a `Detail` map. A new
`swipe_acts` table records each act by client id with what it replaced, so a repeat returns the stored result and undo can restore it.

**Tech stack:** .NET 10 minimal APIs, Dapper/Npgsql, xUnit + Testcontainers + `WebApplicationFactory`; plain JS for the PWA (no framework, CSP
`script-src 'self'`).

**Spec:** `docs/specs/2026-10-19-v1.0-app.md` (Server 2 and 3). Master plan: `docs/plans/2026-10-19-v1.0-app.md` (step 2).

## Global constraints
- Swipe mode's guards stay: dwell never feeds ranking; the swipe path calls no LLM; card text is rendered with `textContent`, links only `http(s)` (`Html.SafeUrl`).
- `/swipe` keeps cookie + `csrf` body field + same-origin; new fields are optional, so a PWA tab open from before the deploy keeps working.
- Every inbox entry written in step 1 has an `ExpiresAt`; any new `InboxStore.AddAsync` caller must pass one (conflicts refresh `expires_at`).
- With `Telegram:Token` set, Telegram output stays as it is today.
- Migration `0030_one_stack.sql`; new tables go into `PostgresFixture.ResetAsync`.
- `dotnet test FeedEater.slnx` (Docker; run outside the Bash sandbox) and `dotnet format --verify-no-changes` before each commit.

## Decisions taken in this plan (rulings against the spec, recorded)
- **R-a. No `ready` digest state.** Without Telegram, `DigestRun` marks the digest `sent` with `sent_count` = its item count: "sent" means delivered to the stack. Avoids a status migration and keeps `ForceAsync`'s "already sent" rule. Cost if wrong: `/ui/digests` says "sent" for a digest nobody received on Telegram.
- **R-b. No release mute.** Nothing in feed-eater mutes a package today (Telegram has no such button); `release` cards get `open` only. The spec's "mute package" moves to a later step if wanted.
- **R-c. Undo scope.** Undoable: like, dislike, save (vote restored; the Karakeep bookmark stays — step 4's library makes save fully undoable), share, open, stop (follow reopened), drop (idea reopened). Not undoable, with a plain answer: idea (filed in Plane), keep (filed in Plane), pick_a/pick_b (duel answered), good/again, send/dismiss.
- **R-d. Re-showing inbox entries.** An entry is queued while `done_at is null`, not expired, and shown fewer than 2 times (`inbox.shown_count`). Acting on it (anything but `open`) sets `done_at`. An entry left twice with `next` drops out without a decision.
- **R-e. Acts on ended sessions** are accepted for 24 hours after the session ended (today they are accepted forever); older ones answer "Nothing to do."

## Review focus
1. **Repeated act.** The same `clientId` twice (sequential and concurrent): one vote write, one Plane item, one follow close; the second call returns the first result. Task 5.
2. **Cap hides the digest.** Digest + inbox + notices > `Swipe:Cards`: the overflow is in the next session's head, none expires early. Task 2.
3. **Digest item already handled.** A digest item voted on Telegram, or shown in an earlier session, is not in the head; a digest item in the head is not also a ranked item in the same session. Task 2.
4. **Old PWA tab.** An `/act` without `clientId` still works exactly as before (no idempotency, no undo). Task 5.
5. **Hostile payload text** in follow/release/idea/review cards: rendered as text; `Detail` values are plain strings; URLs pass `Html.SafeUrl`. Tasks 3 and 7.

alter table inbox add column shown_count int not null default 0;

alter table swipe_events drop constraint swipe_events_action_check;
alter table swipe_events add constraint swipe_events_action_check check (
    action in ('next', 'back', 'like', 'dislike', 'save', 'share', 'idea', 'open', 'good', 'again', 'send', 'dismiss',
               'stop', 'pick_a', 'pick_b', 'keep', 'drop'));

-- One row per act the client sent with an id. A repeat returns this row's result; undo restores previous_*.
create table swipe_acts (
    client_id       uuid primary key,
    session_id      bigint not null references swipe_sessions (id) on delete cascade,
    position        int not null,
    act             text not null,
    ok              boolean,                 -- null while the first call is still running
    message         text,
    previous_value  smallint,                -- the vote before the act; null = there was none
    previous_weight real,
    at              timestamptz not null default now(),
    undone_at       timestamptz
);
create index swipe_acts_card_idx on swipe_acts (session_id, position);

    public async Task<IReadOnlyList<long>> DigestSlotsAsync(DateTimeOffset sentAfter, CancellationToken ct)
    {
        await using var c = await db.DataSource.OpenConnectionAsync(ct);
        return (await c.QueryAsync<long>(new CommandDefinition(
            """
            with latest as (
                select item_ids from digests where status = 'sent' and sent_at > @sentAfter order by local_date desc limit 1)
            select d.id from latest, unnest(latest.item_ids) with ordinality as d(id, n)
            where not exists (select 1 from votes v where v.item_id = d.id)
              and not exists (select 1 from swipe_events e where e.kind in ('item', 'digest') and e.ref_id = d.id)
            order by d.n
            """, new { sentAfter = sentAfter.UtcDateTime }, cancellationToken: ct))).ToList();

```csharp
using Dapper;
using FeedEater.Storage;

namespace FeedEater.Swipe;

public sealed record ActRecord(Guid ClientId, long SessionId, int Position, string Act, bool? Ok, string? Message, short? PreviousValue, float? PreviousWeight,
    DateTime At, DateTime? UndoneAt);

/// <summary>Acts the client sent with an id. The insert is the claim: a second call with the same id finds the row and runs nothing.</summary>
public sealed class SwipeActStore(FeedDb db)
{
    private const string Columns = "client_id, session_id, position, act, ok, message, previous_value, previous_weight, at, undone_at";

    public async Task<ActRecord?> ClaimAsync(Guid clientId, long sessionId, int position, string act, (short Value, float Weight)? previous, CancellationToken ct)
    {
        await using var c = await db.DataSource.OpenConnectionAsync(ct);
        var inserted = await c.ExecuteAsync(new CommandDefinition(
            """
            insert into swipe_acts (client_id, session_id, position, act, previous_value, previous_weight)
            values (@clientId, @sessionId, @position, @act, @value, @weight) on conflict (client_id) do nothing
            """, new { clientId, sessionId, position, act, value = previous?.Value, weight = previous?.Weight }, cancellationToken: ct));
        return inserted == 1 ? null : await GetAsync(clientId, ct);
    }

    public async Task CompleteAsync(Guid clientId, bool ok, string message, CancellationToken ct)
    {
        await using var c = await db.DataSource.OpenConnectionAsync(ct);
        await c.ExecuteAsync(new CommandDefinition(
            "update swipe_acts set ok = @ok, message = @message where client_id = @clientId", new { clientId, ok, message }, cancellationToken: ct));
    }

    public async Task<ActRecord?> GetAsync(Guid clientId, CancellationToken ct)
    {
        await using var c = await db.DataSource.OpenConnectionAsync(ct);
        return await c.QuerySingleOrDefaultAsync<ActRecord>(new CommandDefinition(
            $"select {Columns} from swipe_acts where client_id = @clientId", new { clientId }, cancellationToken: ct));
    }

    /// <summary>False when it was undone already.</summary>
    public async Task<bool> MarkUndoneAsync(Guid clientId, DateTimeOffset at, CancellationToken ct)
    {
        await using var c = await db.DataSource.OpenConnectionAsync(ct);
        return await c.ExecuteAsync(new CommandDefinition(
            "update swipe_acts set undone_at = @at where client_id = @clientId and undone_at is null", new { clientId, at = at.UtcDateTime }, cancellationToken: ct)) == 1;
    }
}
```

```csharp
    /// <summary>
    /// Notices, the latest digest's unhandled items and open inbox entries come first, in that order and unshuffled; then due recall cards and seeds
    /// (up to their limits) and ranked items fill the rest, shuffled together.
    /// </summary>
    internal async Task<IReadOnlyList<QueuedCard>> BuildQueueAsync(DateTimeOffset now, CancellationToken ct)
    {
        var o = Settings.Swipe;
        var entries = await inbox.EligibleAsync(now, o.Cards, ct);
        var digest = await store.DigestSlotsAsync(now.AddDays(-3), ct);
        var head = entries.Where(e => e.Kind == InboxKinds.Notice).Select(e => new QueuedCard(e.Id, null, "notice", null, "notice"))
            .Concat(digest.Select(id => new QueuedCard(id, null, "digest", null, "digest")))
            .Concat(entries.Where(e => e.Kind != InboxKinds.Notice).Select(e => new QueuedCard(e.Id, null, "inbox", null, e.Kind)))
            .Take(o.Cards).ToList();

        var special = new List<QueuedCard>();
        var room = o.Cards - head.Count;
        if (o.Recall.Enabled && room > 0)
        {
            special.AddRange((await recall.DueAsync(now, Math.Min(o.Recall.PerSession, room), ct)).Select(c => new QueuedCard(c.Id, c.Category, "due", null, "recall")));
        }

        if (o.Seeds.Enabled && room - special.Count > 0)
        {
            special.AddRange((await recall.NewSeedsAsync(Math.Min(o.Seeds.PerSession, room - special.Count), ct)).Select(x => new QueuedCard(x.Id, x.Category, "seed", null, "seed")));
        }

        var rest = await BuildItemQueueAsync(Math.Max(0, room - special.Count), digest, now, ct);
        var random = new Random();
        return [.. head, .. rest.Concat(special).OrderBy(_ => random.Next())];
    }
```

### Task 5: idempotent acts, undo, 24-hour window

**Files:** modify `SwipeService.cs` (`ActAsync(…, Guid? clientId)`, new `UndoAsync`, `QueuedAsync`), `SwipeEndpoints.cs` (`ActBody.ClientId`,
`UndoBody`, `POST /swipe/undo`). Test: create `tests/FeedEater.Tests/SwipeActTests.cs`.

**Interfaces produced (step 3 uses them unchanged):**
`SwipeService.ActAsync(long sessionId, int position, string act, Guid? clientId, CancellationToken) → ActResult`;
`SwipeService.UndoAsync(long sessionId, int position, Guid clientId, CancellationToken) → ActResult`;
`public sealed record ActBody(string? Csrf, long Session, int Position, string? Act, string? ClientId);`
`public sealed record UndoBody(string? Csrf, long Session, int Position, string? ClientId);`

Behaviour:
- `clientId` null → exactly today's behaviour.
- With an id: read the card's current vote (`VoteOfAsync` on the item the act touches, for like/dislike/save), `ClaimAsync`; a stored record →
  return `ActResult(record.Ok ?? true, record.Message ?? "Already done")` without running anything; else run the act, `CompleteAsync`, return.
- A claim whose session/position differ from the stored one → `ActResult(false, "Nothing to do.")`.
- `UndoAsync`: record must exist, match session/position, be ok, not undone, and be under 24 h old; then per ruling R-c: restore the vote
  (`SetVoteAsync(item, previousValue, previousWeight)` or `ClearVoteAsync` when there was none), reopen the follow (`FollowStore.ReopenAsync`) and
  the inbox row (`InboxStore.ReopenAsync`), or for drop: `InboxStore.ReopenAsync` and delete the `weekly_ideas` row with `outcome = 'dropped'` for the
  payload url (add `WeeklyIdeaStore.UndropAsync(canonicalUrl)`); remove the act from the event's `acts` and recompute `action` with `Primary`;
  `MarkUndoneAsync`. Not undoable → `ActResult(false, "Can't undo that: …")` with the reason (filed in Plane, duel answered, recall reviewed, seed handled).
- `QueuedAsync` (used by act and event): reject when the session ended more than 24 h ago.
